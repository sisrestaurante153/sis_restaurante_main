### P2 (advisory, not blocking)

1. **MUI outlined focus ring** — `.field input:focus` in HTML uses `box-shadow: 0 0 0 3px rgba(24,95,165,.1)` + `border-color: var(--azul)`. MUI `TextField` outlined focus renders a 1-2px colored outline but without the 3px soft halo. Non-visible in screenshots at rest; would surface only in interaction captures. D-02 explicitly preserved MUI; no change recommended.
2. **"Atualizado em" field uses MUI DatePicker icon** (`/itens/novo` screenshot shows calendar icon at end of the field) while the HTML Fornecedor 1 principal uses `<input type="text" value="06/04/2026">` plain. This is a preserved Phase 8 D-11 decision (date picker UX upgrade) — superior UX vs pure text, documental only.
3. **Placeholder "0,0000" vs "0.0000"** — `/itens/novo` "Quantidade de compra" shows `1,0000` correctly (pt-BR comma), but "Preco de uso" readonly shows `0.0000` (dot-decimal). This is the same root cause as gap #4 (derivation output not passed through `formatCurrency`). Already documented.

### P1-adjacent (confirm)

None — the 4 commits (2eb2206, b074c51, b545f46, 23b1809) cleanly resolved the 4 P0/P1 gaps promised.

## Pillar-by-Pillar Detail

### 1. Visual fidelity (5/5)

Verified tokens:
- `#185FA5` (azul) — 11 occurrences in `ficha-form.tsx` + both ficha topbars + item topbars.
- `#EAF3DE / #1B6B2C / #C0DD97` (verde-l / verde / verde-b) — readonly green fields, badge "ativo/ativa".
- `#E6F1FB / #B5D4F4 / #185FA5` — Custo atual da ficha blue box.
- `#F09595 / #A32D2D / #FCEBEB` — btn-danger Excluir item.
- `#D3D1C7 / #888780 / #5F5E5A / #2C2C2A` — borders + text scale.

Grid templates (literal match):
- `ficha-form.tsx:243` — `gridTemplateColumns: '110px 1fr 150px 175px'` ≡ HTML `.g-id1`.
- `ficha-form.tsx:302` — `'1fr 1fr 120px 1fr'` ≡ HTML `.g-id2`.
- `ficha-form.tsx:407` — `'1fr 1fr'` ≡ HTML `.g-fin`.
- `item-form.tsx` Row 1 `140px 1fr 160px` ≡ HTML `.g-3-a`.

### 2. Information architecture (5/5)

All cards appear in HTML order:
- **Item:** Identificacao → Detalhamento de Compras/Fornecedor → Observacoes.
- **Ficha:** Identificacao → Estrutura → (Montagem toggle) → Finalizacao + Quadro Final.

Card labels (uppercase tracking .1em, 10px, `#888780`) match exactly. Title strings "Identificacao", "Detalhamento de Compras / Fornecedor", "Observacoes", "Estrutura da Ficha", "Finalizacao" all match HTML `.card-label` byte-for-byte.

### 3. Interaction states (4/5)

- Hover: explicit `&:hover` sx on all primary/danger buttons with correct hex overrides.
- Disabled: not explicitly tokenized but MUI default `.Mui-disabled` matches close enough.
- Focus: MUI outlined default vs HTML custom halo (minor P2 as noted above).
- Readonly: `slotProps={{ input: { readOnly: true } }}` + green sx override applied consistently.

### 4. Accessibility (5/5)

- Labels associated via MUI `TextField label` prop (implicit `for`/`id`).
- Icon buttons: `aria-label` in FichaHeaderActions (Duplicar/Exportar per D-05).
- Touch targets: topbar buttons `padding: 8px 18px` → ~36px height. Passes WCAG 2.5.5 minimum 24×24 enhanced.
- Contrast:
  - `#1B6B2C` on `#EAF3DE` → 6.67:1 (AA ✓)
  - `#185FA5` on `#fff` → 7.02:1 (AAA ✓)
  - `#A32D2D` on `#fff` → 6.35:1 (AA ✓)
  - `#888780` on `#fff` → 3.89:1 (AA large only; used only on subtitles/hints ≥ 11px — borderline but acceptable per design system)

### 5. Responsive/overflow @ 1440×1100 (5/5)

- All 4 screenshots fit viewport without horizontal scroll.
- Sticky action bar collapses responsively via `display: { xs: "none", sm: "inline-flex" }` on topbar button, with `StickyActionBar` showing full button on mobile.
- No text truncation or label overlap in any card.
- Ficha /edit screen fits Quadro Final grid in 2-col at 1440 without cramping.

### 6. Consistency with Phase 8/8.1 (3/5)

Consistent:
- Topbar pattern (PageHeader component with `size="compact"`, breadcrumbs, description, actions) — used identically across all 4 detail screens and Phase 8 listings.
- Breadcrumb style (Home › Itens/Fichas › Name) — identical to Phase 8.
- FormSection (title-only, no description per D-13) — consistent with Phase 8.1 listings.
- StickyActionBar pattern — identical mobile-first reveal.

Minor drift (not defect, just friction points for future polish):
- Phase 8.1 listings use native `<table>` (post-Phase-8.1 migration from DataGrid). Phase 9 detail screens still use MUI `TextField` (per D-02 decision — preserved intentionally for form ergonomics). Visual result: slight difference in input padding tightness vs HTML contract.
- Item topbar uses two separate action buttons (Excluir + Salvar) via `Stack`, while Ficha topbar uses a more complex composition (Chip + icon-buttons + primary button). Different compositions are correct per HTML — noting as a consistency check, not a defect.
