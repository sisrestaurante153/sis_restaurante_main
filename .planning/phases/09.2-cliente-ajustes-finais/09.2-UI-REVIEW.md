## Section 2 — 6-pillar audit

### Pillar 1 — Visual fidelity vs HTML refs (5/5)
- **tela-item-v1 (screens 01/02):** structure, card chrome (double-nested subtle bg), fornecedor
  card header, label positions (floating MUI label over input), green-tinted derived cells
  (Fator de conversao, Preco de uso) all match. Button position for A1 matches HTML y~1153.
- **tela-ficha-tecnica-v2 (screens 03/04):** Quadro Final strip + 2-col + 4-col grids,
  amber/green semantic backgrounds, inline inputs in Venda e Margem, diagnostic banner all match.
- No hex mismatches observed at screenshot resolution. Tokens from B4 rewrite (`--verde`,
  `--ambar`, `--azul`) render consistent with HTML preview.

### Pillar 2 — Information architecture (5/5)
- Top-to-bottom reading order aligned with mental model (identificacao → estrutura → preparo →
  resultado financeiro). B3 delivered the UX improvement: user fills preparo BEFORE seeing margin math.
- Grouping: Detalhamento de Compras rolls up all supplier rows + footer action into one card
  (A1 pattern). Montagem block encapsulates table + add action (B2 pattern). Consistent.

### Pillar 3 — Interaction states (4/5)
- **Focus visible** in screen 01 (orange/amber outline on `Unidade de compra` Select) — A11Y good.
- Edit state screens (02, 04) show populated values, disabled-looking derived cells with the
  green tint (intentional: "calculado automaticamente" affordance).
- **Minor (-1):** Screenshot 03 (empty `fichas/nova`) shows Custo base da ficha pill as
  `R$ 0,00` — acceptable empty state but no skeleton for the `QUADRO FINAL` sections; user
  sees full 4-block layout with zeros which can feel noisy on a brand-new ficha. Cosmetic only;
  not a cliente ask. **Recommendation:** collapse Quadro Final blocks until at least one
  ingredient is added, or render a single empty-state card. Deferred to future polish phase.

### Pillar 4 — A11y (4/5)
- Labels present on all inputs (MUI floating labels). Required fields marked with `*`.
- Semantic section headers (`IDENTIFICACAO`, `ESTRUTURA DA FICHA`, etc.) present — screen readers get structure.
- **Minor (-1):** The new `Montagem e Descartaveis` toggle in the Custos e CMV card (B4 rewrite)
  uses a custom `<Box component="input">` per SUMMARY D-02 note. SUMMARY's "Next steps"
  explicitly calls out ARIA validation pending for this toggle. Not blocking but flag for
  follow-up. (Cannot verify ARIA from screenshot alone — requires DOM inspection.)

### Pillar 5 — Responsive (assumed 4/5)
- Screenshots captured at single viewport. Grids in Quadro Final use CSS grid with sensible
  column counts (5 for Pesos, 2 for Custos/Venda, 4 for Leitura) that should reflow on tablet
  per HTML ref behavior. **Not directly verified** at mobile/tablet viewports in this audit
  batch — inherit Phase 9.1 score.

### Pillar 6 — Consistency (5/5)
- Pattern: "Adicionar X" actions now live at the FOOTER of their parent card across the app
  (A1 fornecedor, B2 montagem item). Cross-screen consistency achieved.
- Derived cells use the same green tint on both Itens (Fator de conversao, Preco de uso) and
  Fichas (Margem de contribuicao R$/%) — single semantic.
- Amber highlight reserved for "summary/alerta" rows (CMV final aplicado, diagnostico) on both
  HTML v2 and the app. Consistent.

**Pillar total: 27 / 30.**

## Section 3 — Net-new divergences introduced by 9.2

**None found.**

Addressing the tertiary hypothesis: the user suggested HTML v2 places FINALIZACAO
**between** Estrutura and Montagem while the app places it after Montagem. Verification against
`docs/qa/html-references/tela-ficha-tecnica-v2.png`:

- HTML v2 order: `ESTRUTURA DA FICHA` (tabs: Ficha tecnica / Biblioteca) → `MONTAGEM E DESCARTAVEIS`
  (as a sub-block INSIDE or adjacent to Estrutura, rendered via toggle) → `FINALIZACAO` → `QUADRO FINAL`.
- App order (screens 03/04): identical. The `Montagem e Descartaveis` block is rendered under
  Estrutura da Ficha (toggle-controlled), then Finalizacao, then Quadro Final.

The hypothesis appears to have conflated Montagem's placement (inside Estrutura in both) with a
FINALIZACAO swap. **No divergence exists.** FINALIZACAO is after Montagem in both the HTML
reference and the implementation — and B3's explicit contract in `09.2-CONTEXT.md` states
exactly this order.

Other checks:
- Secondary-supplier `Unidade de uso` readonly badge (D-05/D-06): preserved; A2 only liberated
  primary-supplier `Unidade de compra`. Correctly scoped.
- `SimilarFichasBanner` removal (B1): no orphaned imports, server action deleted per SUMMARY.
- B4 Quadro Final rewrite used inline `<Box component="input">` for Venda e Margem inputs to
  hit pixel-perfect HTML sizing (SUMMARY D-02). Test `toHaveValue("")` asserts preserved —
  no behavioral regression.
