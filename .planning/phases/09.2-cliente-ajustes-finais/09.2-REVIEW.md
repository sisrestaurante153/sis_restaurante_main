## Info (P2 — polish, nao bloqueia)

### IN-01: `quadroFinalSummary` inicia como `null` — um frame sem Quadro Final no mount

**File:** `src/modules/engineering/ui/ficha-form.tsx:166-167`
**Issue:** `useState<ComponentsEditorSummary | null>(null)` faz o Quadro Final so aparecer
depois do primeiro `useEffect` do `<QuadroFinalPublisher>` rodar. Em edicao de ficha existente
(`initialValues?.summary` ja tem dados completos), ha um frame de CLS onde o card nao renderiza.
**Fix:**
```tsx
const [quadroFinalSummary, setQuadroFinalSummary] =
  useState<ComponentsEditorSummary | null>(initialValues?.summary ?? null);
```
Opcional — o effect fechara o gap em <16ms e todos os tests passam, mas melhora a primeira
renderizacao de paginas `/fichas/[id]`.

### IN-02: Comentario `PDFV2-FICHA-07` stale em `ficha-form.tsx`

**File:** `src/modules/engineering/ui/ficha-form.tsx:143-144`
**Issue:** O comentario diz "estado controlado do Modalidade. O input continua como
name=\"modalityId\" no form submit, apenas o valor se torna controlado" — mas o rationale
original (alimentar `findFichasUsingItem`) foi removido em B1. O state `modalityId` ainda e
usado legitimamente (select controlado com erro inline), so o label PDFV2-FICHA-07 e obsoleto.
**Fix:** Substituir por comentario neutro ex. `// Estado controlado do select Modalidade (erro inline + submit via name="modalityId").`.

### IN-03: Atributo `step` dead-code em inputs `type="text"` (B4)

**File:** `src/modules/engineering/ui/TotaisIndicadores.tsx:695,751`
**Issue:** Elementos `<input type="text" inputMode="decimal" step="0.01">` e
`step="0.5"` — o `step` attribute e especifico para `type="number"` e silenciosamente ignorado
em inputs texto. Nao causa bug, so gera noise no HTML renderizado.
**Fix:** Remover as props `step` dos dois inputs ou converter para `min`/`max`/`pattern` se houver intencao validadora.

### IN-04: `QuadroFinalPublisher` usa `JSON.stringify` como dep key do effect

**File:** `src/modules/engineering/ui/components-editor.tsx:668-673`
**Issue:** Padrao funcional mas cria uma string completa a cada render do pai. Para payloads
pequenos (state atual: ~200 caracteres) o custo e desprezivel; em `summary` crescer muito isso
pode pesar. Alternativa mais idiomatica React: `useMemo`+`useEffect(state)` com comparacao shallow
via `useRef` OU mover para `useSyncExternalStore` patterns. Nao bloqueia.
**Fix (opcional):**
```tsx
const ref = useRef(state);
useEffect(() => {
  if (!shallowEqual(ref.current, state)) {
    ref.current = state;
    onChange(state);
  }
});
```
