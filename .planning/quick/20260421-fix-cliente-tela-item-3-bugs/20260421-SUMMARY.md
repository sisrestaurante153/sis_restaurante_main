## T1 — Fornecedor 2 nao some mais + erros per-row visiveis

**Commit:** `888bc8a` — `fix(quick-20260421): T1 — Fornecedor 2 nao some mais + erros per-row visiveis`

**Diagnostico:** O cliente reportou "Fornecedor 2 some da tela" apos salvar.
Causa raiz identificada via leitura do codigo (conforme constraint "se
verificar via leitura que bug e APENAS UX silenciosa"):

1. `buildAdditionalRow` em `purchases-editor.tsx` pre-preenchia
   `purchaseCost: "0.0000"` — `positiveDecimal` do Zod (`> 0`) rejeita
   esse valor silenciosamente.
2. `parseItemFormData` usava `parsed.error.flatten().fieldErrors`, que em
   Zod 3 **descarta todos os erros aninhados de arrays** (`purchases[N].campo`).
   A UI recebia apenas a mensagem generica "Revise os campos do item."
   sem saber qual campo de qual fornecedor reprovou.
3. Em reload pos-save (tanto apos sucesso quanto refresh manual), o
   form reinicializa com `initialValues` do repository. Como Fornecedor 2
   nunca foi persistido (validacao reprovou), o usuario percebe que "sumiu".

**Arquivos tocados:**

- `src/modules/catalog/ui/purchases-editor.tsx`:
  - `buildAdditionalRow()`: `purchaseQuantity` e `purchaseCost` passam de
    `"1.0000"` / `"0.0000"` para string vazia. Placeholder `"0,0000"` e
    `"R$ 0,00"` (ja existentes) passam a ser visiveis, forcando o usuario
    a preencher.
  - Novo prop `rowErrors?: Record<string, string[] | undefined>` no
    `PurchasesEditorProps`.
  - Novo helper `summarizeRowErrors()` que extrai entries das keys
    `purchases.<index>.<campo>`.
  - Novo Alert severity=error acima do primeiro card quando existem
    `rowErrors`, com label amigavel por campo (ex.: "Fornecedor 2 —
    Preco de compra: Deve ser maior que zero.").

- `src/modules/catalog/server/item-form-schema.ts`:
  - `parseItemFormData` agora combina `.flatten().fieldErrors` (top-level)
    com iteracao sobre `parsed.error.issues` para emitir keys no formato
    `"purchases.<index>.<campo>"` sempre que `issue.path[0] === "purchases"`
    e `path.length > 1`.

- `src/modules/catalog/ui/item-form.tsx`:
  - Propaga `state.errors` para `<PurchasesEditor rowErrors={...} />`.

- `src/tests/unit/item-form-schema.test.ts`:
  - +1 it() "preserva erros aninhados per-row em keys purchases.N.campo
    (Quick 20260421 T1)". Verifica que `purchases.1.supplierName` e
    `purchases.1.purchaseCost` estao definidos no errors map e que
    `purchases.0.*` continua undefined (principal valido).

**Verificacao:**
