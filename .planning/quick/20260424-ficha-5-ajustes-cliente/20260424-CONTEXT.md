<decisions>
## Implementation Decisions

### Item 1 — Picker por código
- **Decisão:** Código + Nome lado a lado. Adicionar pequeno campo "Código" à esquerda do atual select "Item".
- **Comportamento:**
  - Digitar código (ex: "ARZ01") + Enter/blur → autocompleta e seleciona o item correspondente em "Item".
  - Selecionar item pelo nome no dropdown → popula o código automaticamente.
  - Campo código aceita texto livre; match é case-insensitive contra `ComponentOption.code`.
  - Se o código digitado não corresponder, campo fica com o texto mas não muda o item (nenhum erro bloqueante).
- **Dados:** `ComponentOption` precisa expor `code` (hoje não expõe). Adicionar no `mapItemOption` do catalog-prisma-mappers.

### Item 2 — Qtde field maior
- **Decisão:** Aumentar coluna Qtde no `GRID_TEMPLATE` de `80px` → `110px`.
- **Também:** Aumentar input padding interno ou remover `textAlign: right` se estiver cortando → manter `textAlign: right` mas com padding right maior (16px) para não cortar o último dígito.

### Item 3 — Unidade select
- **Decisão:** Substituir TextField livre por TextField `select` populado via `listUnits()` do master-data repository.
- **Fonte:** `getMasterDataRepository().listUnits()` → filtra `active === true` → usa `.code` (ex: kg, g, l, un).
- **Fallback:** Se `listUnits()` falhar/retornar vazio, manter fallback `["kg", "g", "l", "ml", "un"]` (lista hoje no purchases-editor).
- **Prop drilling:** adicionar `unitOptions: string[]` na prop de `FichaFlatGrid` e de `ComponentsEditor`. Carregar nas páginas `fichas/[fichaId]/page.tsx` e `fichas/nova/page.tsx` junto com os outros `itemOptions`/`stageTypes`.

### Item 4 — FC/IC per-row calculado
- **Decisão:** Mostrar valor calculado na coluna `Peso` quando a linha tem stage selecionado.
  - `stageCode === "limpeza_pre_preparo"`: exibir FC = `peso_limpo / qtde_usada` (decimal 4 casas) formatado como %.
  - `stageCode === "coccao_preparo"`: exibir IC = `peso_pos_coccao / qtde_usada` (decimal 4 casas) formatado como %.
  - `peso_limpo` / `peso_pos_coccao` = `row.outputWeight`.
  - `qtde_usada` = `row.quantityUsed`.
  - Se `outputWeight` ou `quantityUsed` <= 0 ou vazio → mostrar `--`.
- **Display:** em vez do texto estático `"FC automatico"` / `"IC automatico"` como helper, trocar por valor calculado no mesmo slot, ex: `FC 85%` ou `IC 120%`.
- **Paridade:** buildFichaIndicators no server já usa essa convenção (Limpo/Bruto e Pós-cocção/Limpo) — estamos espelhando.

### Item 5.1 — Alinhar Coccao Final ao grid normal
- **Decisão:** Remover `CF_GRID_TEMPLATE` e usar o mesmo `GRID_TEMPLATE` das linhas regulares.
- **Slots:**
  - Drag handle (desabilitado) → `22px`
  - Label "Coccao Final" (substitui coluna Item) → `1fr`
  - Coluna Qtde (vazia ou `--`) → `80-110px`
  - Coluna Unidade (vazia ou `--`) → `80px`
  - Etapa/Peso (subgrid 2 col): Etapa = "Coccao / Preparo" readonly + Peso = input "Rendimento da Porção"
  - Custo unit (vazio) → `90px`
  - Custo insumo (vazio) → `96px`
  - Remove button → `28px`

### Item 5.2 — IC calculado no Coccao Final
- **Decisão:** Popular o TextField "IC" existente (linha 426-437) com valor calculado.
- **Fórmula:** `rendimento_porcao / soma_qtde_usada_todas_linhas` (paridade com `indicators.cookingIndex` do server e com imagem do cliente).
  - `rendimento_porcao` = `coccaoFinalEntry.row.outputWeight`
  - `soma_qtde_usada` = soma de `normalizeQuantity(row.quantityUsed, row.usageUnit)` para todas as regularRowIndices.
- **Format:** `(ic * 100).toFixed(0) + "%"` ou `"--"` se inválido.

### Claude's Discretion
- Label format para FC/IC per-row: `(factor * 100).toFixed(0) + "%"` (arredonda para inteiro, ex: `85%`). Se ficar estranho visualmente, fallback para 1 casa decimal.
- Exato tamanho do campo Qtde: 110px (entre o atual 80 e um ideal 120 — balanço entre fit e não cortar).
- Posição do campo código: à ESQUERDA do item select (antes do campo Item); largura ~72px.
- Se `listUnits()` não estiver disponível na versão demo, carregamos via getMasterDataRepository() com fallback.
