# Quick Task 20260424 — Fornecedor 2+ inputs digitáveis fundo branco

## Resultado

Inputs editáveis do `PurchasesEditor` agora forçam `bgcolor: "#FFFFFF"`, neutralizando a herança do card secundário verde (`#F0F7E8`). O card mantém o tint secundário; campos readonly calculados (`readonlyGreenSx` #EAF3DE) permanecem verdes — alinhado ao spec HTML `update/tela-item-v1.html` linhas 75, 91-92, 98.

## Design contract

Referência autoritativa: HTML do cliente
- Linha 75: `input/select { background: #fff; }` — todos inputs brancos
- Linha 91-92: `.calc { background: var(--verde-l); }` — apenas readonly calculados
- Linha 98: `.fornecedor-block + .fornecedor-block { background: #F0F7E8; }` — apenas o container secundário tem tint

MUI não herdava a cor do card para o input (o OutlinedInput é transparente), então o fundo do card vazava visualmente. O fix adiciona `editableWhiteSx` para forçar branco no `.MuiInputBase-root`.

## Implementação

**Arquivo:** `src/modules/catalog/ui/purchases-editor.tsx` (+14/-1)

- Adicionado `editableWhiteSx` constant (linhas 228-232) ao lado de `readonlyGreenSx`
- Aplicado `sx={editableWhiteSx}` em 7 pontos do layout desktop:
  1. Autocomplete Fornecedor (renderInput TextField)
  2. DatePicker "Atualizado em" (slotProps.textField.sx)
  3. TextField "Unidade de compra" (select)
  4. TextField "Unidade de uso" — apenas branch `isPrimary` (editável)
  5. TextField "Quantidade de compra"
  6. TextField "Quantidade de uso" — apenas branch `isPrimary` (editável)
  7. TextField "Preco de compra"

NÃO tocado:
- Campos com `readonlyGreenSx` (Fator de conversao, Preco de uso, Unidade/Quantidade de uso fixadas em secundário) — mantêm verde claro
- Layout mobile — fora do escopo (cliente só marcou desktop no print)
- Container do card — tint secundário preservado
